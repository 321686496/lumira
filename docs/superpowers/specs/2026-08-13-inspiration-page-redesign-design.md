# 灵感页重构设计（纯本地拍照灵感流）

> 日期：2026-08-13
> 状态：待用户确认
> 范围：Flutter 端（`lumira_app_flutter/`），后端零改动

## 1. 背景与问题

当前灵感页（`lib/features/inspiration/pages/inspiration_page.dart`）存在四类问题：

1. **定位冲突**：名为"灵感"，内容却全是"我的心情统计 / 我的穿搭日记 / 我的场景推荐"——本质是用户历史数据的二次陈列，不是"拍照灵感"。
2. **与首页重复**：2×2 推荐场景网格与首页「场景推荐」同组件、同数据源（SceneRecoCard + mock），入口没有区分。
3. **无效控件**："加载更多灵感"按钮无点击行为；"今日心情"7 个 pill 全部只读，无法点击。
4. **探店打卡入口缺失**：uni-app 原型第三区块「探店打卡」在 Flutter 版灵感页被移除，但完整功能已实现在「我的-探店足迹」（`checkin_list_page` + 本地 DAO），灵感页没有承接。

## 2. 目标与边界

### 目标

把灵感页做成**打开就有拍照冲动、知道拍什么、知道怎么拍**的**纯本地拍照灵感流**。

### 硬性约束（来自用户）

- **纯本地**：不展示、不采集、不上传任何他人生成内容或用户上传内容。
- **避开上架合规审核**：所有"看什么"素材必须为 App 内置静态资源（`assets/images/**`），不请求服务器内容流，不做用户生成内容（UGC）。
- 个性化仅使用**设备内本地 SQLite 拍摄记录**（`gallery` 表），且只用来排序/筛选内置素材，绝不外发。
- 心情 pill 功能**不能删除**，需安置到更合适的入口（见 §6）。

### 非目标（本迭代不做）

- 不做后端内容流 / 社区 / 精选接口（后端零改动）。
- 不做用户上传图片流。
- 不做分享/关注/点赞等社交功能。
- 不改首页已有模块。

## 3. 页面定位与内容架构

页面上到下共 4 个区块，全部**可点击、有去处**，不出现死按钮：

| # | 区块 | 承载的问题 | 数据来源 | 点击去向 |
|---|---|---|---|---|
| 1 | 顶部灵感引导条 | 现在适合拍什么 | 复用 `InspirationService`（时段×天气×本地偏好） | 直接进入匹配的拍摄场景 |
| 2 | 今日可拍（拍什么） | 我该拍点啥 | 本地场景库 `capture_scene_mock_data.dart`（18 个内置场景）+ 本地拍摄统计排序 | 进入场景拍摄引导 `capture_scene_guide` / 场景详情 |
| 3 | 拍得更好（怎么拍） | 我想拍得好看 | 学院内置课程 `academy_content.dart`（16 门，含封面与详情） | 进入学院课程详情 `academy_detail` |
| 4 | 灵感图集（看什么） | 没欲望、没动力 | App 内置模板/剪影/场景静态图 `assets/images/**` | 进入对应模板详情或场景详情，可直接拍摄 |

### 3.1 顶部引导条

- 数据：复用 `homeInspirationProvider`（`InspirationService`：当前时段 × 天气 × 本地最近 30 天主拍类别）。
- 形态：单行轻量提示，如「下午黄金时刻 · 适合拍人像」。
- 交互：整条可点，点击进入当前匹配场景的拍摄引导页；天气/服务失败时降级为通用文案，不阻塞页面。

### 3.2 今日可拍（拍什么）

- 内容：从内置 18 个场景中按「时段匹配 + 你的本地拍摄统计」推荐 4 个。
- 复用：`SceneRecoCard`（与首页一致）+ 场景自带的 `vibe / bestTime / tips / image`。
- 交互：点击卡片 → `capture_scene_guide?scene=<id>`（拍摄引导/直接开拍）；"查看全部场景"入口 → 现有场景库页，避免死链。
- 每日按本地数据刷新，不请求网络。

### 3.3 拍得更好（怎么拍）

- 内容：精选 3 条内置拍摄技巧（光线/构图/角度/氛围），直接复用 `AcademyContent.courses` 的前几条或按本地偏好选择。
- 形态：横向小卡（封面图 + 标题 + 一句话摘要）。
- 交互：点击 → 学院课程详情页 `academy_detail`（已有页面，含完整方法论）；右上或左下可加"全部课程"入口。

### 3.4 灵感图集（看什么）

- 内容：瀑布流展示 **App 内置静态素材**：模板封面 `assets/images/templates/**`、剪影 `assets/images/silhouettes/**`、场景图 `assets/images/scenes/**`，每条配一句内置标题文案（如「咖啡厅窗边 · 午后胶片感」）。
- 数据：全部来自打包资源；不与相册、服务器、用户内容关联。
- 交互：点击图片 → 对应模板详情页（已有）或场景详情页；模板点击后可在详情页直接"去拍摄"。
- 兜底：无数据时显示内置空态引导（"拍下第一张"→ 拍摄页），不用网络占位图。

## 4. 删除项

- `MoodCard` 从灵感页移除（功能迁移至拍摄日记页，见 §6）。
- `OutfitDiaryCard` / 穿搭日记卡从灵感页移除（属于拍摄日记，已有独立页面）。
- 灵感页 2×2 mock 场景网格（与首页重复）移除。
- `_LoadMoreButton` 死按钮移除。
- `InspirationMockData`（moods/outfitPhotos/streak/scenes/subtitle）按实际引用清理，仅保留仍被复用的部分。
- 灵感页旧的路由跳转（`galleryDiary` 等）随组件清理。

## 5. 个性化逻辑（纯本地）

只使用两类本地数据，全部在设备内：

1. `GalleryDao` 统计：最近照片的 `category` / `sceneId` / `templateId` 分布。
2. 当前时段 + 可选天气（已有 `InspirationService`，失败自动降级）。

推荐规则的默认实现：

- **今日可拍**：优先推荐"用户最近主拍类别"对应的内置场景；无数据时按时段默认推荐（晨→窗边光、午→咖啡馆/室内、傍晚→黄昏剪影、夜→霓虹）。
- **拍得更好**：优先展示与用户主拍类别相关的技巧课程；无数据时展示固定精选。
- **灵感图集**：固定瀑布流（内置素材随机洗牌一次，保证每次进来不单调；不依赖用户数据）。

## 6. 心情 pill 迁移方案（不删除）

灵感页顶部心情统计迁移到**拍摄日记页**，与现有 `gallery.mood` 数据形成闭环：

- 拍摄日记页（`gallery_diary_page.dart`）顶部新增**心情分组/筛选**行：沿用现有 7 个心情 pill。
- 选中某心情 → 日记时间线仅展示该心情的照片（读取 `GalleryDao` 的 `mood` 字段，本地过滤）。
- 不选中 → 展示全部。
- 拍摄预览页已有"拍摄前选心情"，至此形成「拍摄前选择 → 日记回顾/筛选」闭环。
- 若用户未在任何照片选过心情，心情 pill 显示空态引导（"拍摄时标记心情，回顾更有温度"），不算功能缺失。

> 注：`gallery_diary_page.dart` 已有未提交的组件改动，实现时需在其基础上增量修改，不覆盖用户已有工作。

## 7. 页面视觉与交互细节

- 保持现有视觉基调：径向渐变背景、玻璃/新拟态风格、`Noto Serif SC` 标题、`FadeUp` 错峰进场。
- `LumiraNav` 标题保持「灵感」，透明背景。
- 每个模块有清晰标题 + 语义图标 + 可点击去处；整体为 `SingleChildScrollView` 纵向布局。
- 无网络依赖：断网时页面照常可用（天气降级、所有内容本地）。
- 空态/降级文案统一：不出现网络错误或 loading 阻塞。

## 9. 验收标准

1. 灵感页首屏无 mock 心情统计、无穿搭日记、无死"加载更多"按钮。
2. 灵感页 4 个区块全部有真实可点击去向；点击"今日可拍"卡片进入场景引导，点击技巧卡进入学院详情，点击图集图片进入模板/场景详情。
3. 断网/天气失败时页面正常渲染（降级文案）。
4. 心情 pill 功能保留：拍摄日记页可按心情筛选；拍摄预览页选心情 → 日记筛选可见。
5. 所有"看什么"图片来自 App 内置 `assets/images/**`，无网络图片、无用户内容。
6. 后端零改动；Flutter 测试全部通过。
7. 不动用户未提交的 `diary_timeline_entry.dart` 与 OHOS 配置改动。

## 10. 风险与说明

- **内容单一风险**：内置素材总量有限，长期可能让用户觉得"翻来覆去就这些"。缓解：瀑布流洗牌 + 后续可扩展内置素材池；本迭代不依赖服务器。
- **个性化程度有限**：仅本地统计决定排序，不做复杂模型。符合"纯本地 + 合规"的硬约束，属于可接受取舍。
- **心情筛选改动涉及已有未提交文件**：实现前需与用户现有改动 diff，尽量在其基础上增量修改并保留其意图。
