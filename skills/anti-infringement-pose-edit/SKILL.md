# 姿势图反侵权批量编辑

## 用途与触发时机

从网上看到喜欢的拍照姿势想做模板,但害怕侵权;AI 直接生成姿势图又太假。本技能对**已有姿势参考图**做人脸改换(完全认不出是同一个人)+ 统一符合场景的衣着,产出可直接用于模板制作的单张成片。

**触发**: 用户给出一组人物图片(≥1 张)并表达"换脸防侵权 / 修改面部/统一衣着/做成姿势模板"等意图时调用。

## 运行前提

- API Key 环境变量(或 `--api-key`)已配置：默认引擎 `qwen3` 走 `MASS_API_KEY`；`--engine gpt2k` 走 `HAPI_API_KEY` —— 复用项目 `scripts/gpt_image2.py` 的 hapi 中转。
- Python 3 + Pillow。裁剪依赖 Pillow,`gpt_image2` 由本技能脚本动态 import 项目 `scripts/gpt_image2.py`。

## 目录


## 生图引擎与单次上限

`--engine` 决定平台/模型/单次输入图片上限（默认 `qwen3` = `mass` / `qwen-image-3.0` / 3 张；`qwen3pro` = `mass` / `qwen-image-3.0-pro` / 3 张；`gpt2k` = `hapi` / `gpt-image-2.5-sunburst-2k` / 4 张），`--max-per-call` 可覆盖。

> ⚠️ **勿用 `qwen3pro` 跑本技能**（2026-10 实测）：mass 平台对生图任务有 **120 秒硬超时**，`qwen-image-3.0-pro` 的换脸级重绘任务耗时 >120s，必然返回 `502 upstream_error: The operation was aborted due to timeout`（输入降到 512、画布大小均无法挽救）。`qwen-image-3.0`（非 pro）同任务仅 31s、宫格 3 图约 90s，可稳定通过且质量肉眼接近 pro。仅改色调/衣着等轻任务用 pro 不会超时。另：`gpt2k`（HAPI）为同步长超时通道，若余额充足可作为重任务备选。
>
> 📐 **mass 平台尺寸说明**（2026-10 实测）：客户端已改走同步 `/v1/images/generations` 端点，`size` 字段（`WxH`）真实生效，且图生图用同端点 `images` 字段（data URL 数组，平台无 `/v1/images/edits`）。仅接受 qwen 官方档位（1024x1024 / 1664x928 / 928x1664 / 1472x1140 / 1140x1472），客户端自动吸附。旧异步 `/v1/generations` 端点忽略 `size`（尺寸字段名为 `resolution`、星号格式），已弃用。

分批与布局规则：首批最多「上限」张（无锚点）；后续每批「上限-1」张目标 + 1 张衣着锚点；批内只剩 1 张时走单图编辑。宫格布局按批内张数与模板比例动态选择（1 张无宫格 / 2 张 1x2 或 2x1 / 3 张 1x3 或 3x1 / 4 张 2x2）。

裁剪出的每格会归一化到统一的目标像素（短边 768、比例 = 模板比例），因此所有成片尺寸完全一致。
另有 `--no-grid`：完全不做宫格打包，每张输入图单独跑一次单图编辑（渠道对多图输入会上游超时时使用）。

## 执行流程

1. **分批**: 按 `--engine` 推导的单次上限切分（默认 `qwen3` 上限 3；`--max-per-call` 可覆盖）, 次序保持输入顺序。
   - 第一批: 最多「上限」张目标图(无锚点, 默认 3);
   - 后续批: 每批 `max_per_call-1` 张目标图 + 1 张"衣着锚点"参考图(首批首张成片), 用于统一衣着。
   - 例: 9 张 → `[3] + [2+锚] + [2+锚] + [2+锚]`。
2. **调用**: 每批通过 `gpt_image2` 的图生图接口(默认 MaaS; `--engine gpt2k` 走 HAPI)一次发出目标图(锚点批次再追加锚点图), 提示词要求模型把每张修改结果按批内张数与模板比例动态选择的宫格布局排成一张图（1x2 / 1x3 / 2x2 及竖排镜像）(左上→右上→左下→右下对应输入顺序, 格间留边框)。默认提示词自带**构图保持硬约束**（景别/人物占比/头顶脚下与四周留白必须与原图一致，禁止推近变焦或裁成特写）；`--hints` 可按输入顺序追加每张图的构图要求（如"全身景别、头顶留白≥15%、禁止裁脚"），宫格按格序拼入、单图编辑附带对应提示；`--engine gpt2k`(hapi 通道) 自动启用 `input_fidelity=high` 提高输入保真。
3. **裁剪**: `crop_grid.py` 用「连续低方差 gutter 带」定位切点——只在期望等分位置近邻（±40% 格宽窗口）内存在真实白缝/留白带时才切、切在带中心以剔除白线；近邻内找不到缝隙则退回均分切，**绝不把切点投进高方差内容区**（修复了旧实现把切点落在人物/场景中间、裁到上下两格交界的情形）。每格切出后再做"均质边净化"(`_purge_uniform_edges`, 上限 30px、std<4)清除网格线残余。对干净宫格可裁出规整单格; 裁不干净的自动单图回退。
4. **回退**: 某格空白/低质, 或在锚点批次被误渲染——对该目标图单独跑一次单图编辑兜底, 保证每张必有输出。
5. **输出**: `--out` 下生成 `out1.png...outN.png`, 与输入顺序一一对应; 打印输入→输出映射与缺失清单。宫格图默认保留到 `out/_grids/batchN.png`(供 QA 对照)。

## 加工后 Agent 视觉 QA 与自动纠错（必做）

> **运行 Agent 的 AI 用「看图的视觉能力」对每张成片 `outN.png` 逐张审查**，判定是否合格；不合格的走自动纠错重生成后再复查。不要相信脚本已经"成功输出"就等于质量合格。

**审查判据（逐张对照 参考原图 + 该格姿势描述 + 模板 `aspect_ratio`）：**

1. **裁剪错位**：每张只含一个完整人物；人物没有被上下/左右切边截断；画面不含邻格的白缝格线、邻格人物肢体、或"两张各半"的内容。
2. **构图忠实度（对照参考原图，重点）**：景别一致（参考是全身则成片必须全身含脚、是半身则不得变成特写）；人物在画面中的位置与大小占比一致；头顶/脚下/四周留白量一致——成片明显比参考更"满"、更推近即为 FAIL，须重生成。
3. **面部可见性一致性（重点）**：原图不露脸（背影/低头/侧后/遮挡）的，成片必须同样不露脸且头部朝向不变——出现补画/脑补的完整面部即为 FAIL（提示词已内置 FACE_VISIBILITY 规则，但模型仍可能违反，QA 必查）；原图露脸的，成片换脸后才算合格。
4. **人物/背景畸变**：人脸换脸成功且自然（不残留原明星脸 → 防侵权达标）；五官、手部、肢体无扭曲/畸形/多余手指；人物与背景光影、透视、比例正常，无漂浮感或明显抠图感。
5. **一致性**：人物姿势与该姿势描述/参考图一致；同批人物衣着统一且贴合场景；画面横竖/画面与模板 `aspect_ratio` 一致；无 AI 感的塑料磨皮/光晕。

**纠错闭环（某张 fail 时）：**

1. **先分类失败原因**：
   - 属**裁剪错位**（人物被切到/邻格串入）→ 直接用保留的 `_grids/batchN.png` 对该格**重新裁剪**校验；不可靠则重跑该批 `run_batch_edit.py <该批参考原图…> --ratio <w:h>`。
   - 属**内容质量**（畸变/换脸失败/一致性差）→ 用该张**已加工成片 `outN.png` 单独重编辑**（保持姿势/衣着/场景，只修瑕疵），附衣着锚点维持统一：
     `python scripts/run_batch_edit.py <outN.png> --anchor <衣着锚点图> --out <out>/_recheck --ratio <w:h>`
2. 对重生成结果**重复上面的视觉审查**（只看重生成的那几张，不重看合格张）。
3. **硬上限：单张重试 ≤3 次、整批返工 ≤2 轮、总耗时预算 ≤15 分钟**。到达任一上限立即停止自动纠错，把不合格项标记 `QA_FAIL` 并保留原成片供人工处理——**严禁无限打磨循环**（历史教训：6 轮 reedit 烧掉 3 小时，而全部 API 调用本身只要几分钟）。
4. 汇总写入 **`out/qa_report.md`**：每张结论（PASS / QA_FAIL / 重试次数 / 失败原因），并把 `_recheck` 里最终采用的那张替换回 `outN.png`。**存在 QA_FAIL 时明确告知用户，不擅自当作成品交付。**

## 用法

```bash
# 基本(9 张示例)
python scripts/run_batch_edit.py a.jpg b.jpg c.jpg d.jpg e.jpg f.jpg g.jpg h.jpg i.jpg \
    --out ./outputs

# 显式覆盖引擎推导的上限
python scripts/run_batch_edit.py 1.png 2.png 3.png 4.png 5.png --max-per-call 4 --out ./o

# 指定引擎(走 hapi, 单次上限 4)
python scripts/run_batch_edit.py 1.png 2.png 3.png 4.png 5.png --engine gpt2k --out ./o

# 指定模板宽高比(影响宫格布局与成片尺寸)
python scripts/run_batch_edit.py 1.png 2.png 3.png 4.png --ratio 3:4 --out ./o

# 附带每张图的构图提示(与输入顺序一一对应, ';;' 分隔)
python scripts/run_batch_edit.py 1.png 2.png 3.png \
    --hints "全身景别，头顶留白≥15%;;半身景别，保持原图占比;;全身景别，禁止裁脚" --out ./o

# 只预览分批/锚点计划, 不调接口
python scripts/run_batch_edit.py img1.jpg img2.jpg ... --dry-run

# 中间宫格拼图默认保留到 out/_grids; 需清理时用 --no-keep-grids
python scripts/run_batch_edit.py ... --no-keep-grids
```

## 关键提示词

默认编辑提示词(可用 `--prompt` 覆盖):

> 修改一下这些图中人物的面部，变得更精致、更帅气美丽、有辨识度；优化衣着，使其更时髦有质感、贴合场景，同时风格统一、配色协调；仅修改人物面部与衣着，使其完全看不出与原图是同一个人，以避免侵权；并统一这几张图中人物的衣着。**严格保持每张原图的构图与取景：景别（全身/半身/特写）、人物在画面中的位置与大小占比、头顶与脚下及四周的环境留白，都必须与原图完全一致；禁止推近变焦、禁止裁切为特写、禁止改变留白与人物位置。**（加粗部分为构图保持硬约束 `COMPOSE_KEEP`，单图提示词同样附加）

自动叠加(多批次): 要求按该批次的动态布局输出、格间留边框、顺序对应输入、保持原姿势只改面部与衣着; `--hints` 提供时再按格序追加各格构图要求。
锚点批次再追加: 说明最后一张是"衣着锚点参考图", 仅参考服饰风格、不渲染进网格。

## 已知假设与局限

- 模型输出不保证是规整宫格 → 用智能裁剪缓解, 裁不干净自动单图回退。
- 格子顺序依赖模型遵守输入顺序 → 按读取顺序映射, 数量/内容异常会触发回退。
- 锚点占用一个每批不超过引擎上限的槽位, 因此后续批次目标图上限为 `max_per_call-1`。
- 使用自定义 `--prompt` 时锚点说明与构图提示都不会自动叠加, 需自行在提示词里注明锚点图(仅参考衣着、输出进网格)与构图要求。
- 构图保持依赖提示词约束 + `input_fidelity`(仅 hapi 通道), 生图模型仍可能偏离原图取景 → **QA 的构图忠实度判据不可跳过**; 个别张构图不合格时, 只对该张用 `--no-grid` 单图重编辑(单图比宫格更忠实), **勿全量重跑**(全量 = N 次调用, 只有合格率持续偏低时才值得整体切换)。
