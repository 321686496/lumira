# 新增 24 个常去场景（本地 Flutter + 后端同步）

## Context（背景与目标）

当前 App 内置 18 个拍摄场景（`ScenePresetsData.allScenePresets`），`/scenes` 由后端 `system_scenes` 表提供。
用户希望补充约 24 个覆盖日常生活 95% 常去地点的场景，使场景库更贴近真实需求。

已确认的需求决策：

- 采纳**全部 24 个**新增场景，每个场景生成 **1 张竖版封面**。

- **本地 Flutter + 后端同步**双向都要落地。

- AI 脚本生成的图片必须**压缩处理**，避免内存占用过大。

> 现状说明（双数据源的坑）：
>
> - `ScenePresetsData.allScenePresets`（18 个）= 内置预设权威清单，驱动详情兜底 / 首页推荐 / 拍摄场景条 / 场景库封面 `localCoverOf`。
>
> - `CaptureSceneMockData.presetScenes`（仅 6 个）= DB 种子源（`_seedScenes`）与 `allScenes` 概览统计源。
>
> - 场景库 grid 封面走 `ScenePresetsData.localCoverOf(id)` **优先本地资产**，所以新增场景必须进 `allScenePresets`，本地封面才会生效（即使后端 exampleImages 是远程 URL）。

## 实施步骤

### Phase A：生成并压缩 24 张封面图片

1. 用现有脚本 `d:\app\projects\photo_post\scripts\gen_image.py` 逐个生成竖版封面。

   - 命令示例：`python gen_image.py "<场景prompt>" --model doubao-seedream-5-0 --size 9:16 --out ./tmp_scenes`

   - 每个场景一个针对性中文 prompt（氛围 + 3:4 竖构图 + 电影感灯光），输出到临时目录。
2. **压缩处理**（硬性要求）：

   - 将生成的大图（PNG，可能数 MB）统一压成 `assets/images/scenes/scene_<id>.jpg`，目标竖版约 600×800、期望单张 < \~400KB。

   - 压缩工具：优先用 Python Pillow（若环境已装）；否则用 Windows 内置 `System.Drawing` 的 PowerShell 一次性脚本 resize+JPEG 编码。实现时先探测可用方案。
3. `assets/images/scenes/` 目录已在 `pubspec.yaml` 的 `assets:` 中注册，**无需**改 pubspec。

### Phase B：Flutter 侧新增 24 个内置预设

- 文件：`lumira_app_flutter/lib/features/capture/data/scene_presets_data.dart`

- 在 `allScenePresets` 末尾追加上述 24 个 `ScenePreset`（复用同文件既有 18 个的写法；`filter/sceneGuide` 字段按需填充，`exampleImages[0]` 指向本地资产）。

- `localCoverOf` 自动生效（命中 `allScenePresets` 且首图为 `assets/`）。

### Phase C：让新增场景在离线 DB 种子中出现（关键补漏）

- 现状：`_seedScenes` 只播种 `CaptureSceneMockData.presetScenes`（6 个），新增场景离线装不上。

- 方案：把 `lumira_app_flutter/lib/core/db/seeders/builtin_data_seeder.dart` 的 `_seedScenes` 数据源从 `CaptureSceneMockData.presetScenes` 改为 `ScenePresetsData.allScenePresets`，一次性让全部内置场景（18+24）进入离线 DB。

  - 低风险：原有 `ConflictAlgorithm.replace`，不会与外键/已有数据冲突。

  - 说明：该改动只影响**新装离线设备**；已安装设备靠场景页 `syncSystem()` 联网同步后端补齐。

- （可选，不阻塞）`CaptureSceneMockData.allScenes` 概览统计仍用旧 6 个，若你希望场景库概览"X 个场景"显示全量，可把 `presetScenes` 委托为 `ScenePresetsData.allScenePresets`——默认不动，避免范围蔓延。

### Phase D：后端同步（`system_scenes` + usage 注册）

- 新增一个 Drizzle/原生迁移 SQL（仿 `018_builtin_scenes_seed.sql` 风格）：

  - 将 24 个场景 `INSERT IGNORE`（或按 id upsert）进 `system_scenes`：`id/name/category/style/icon/vibe/description/filter_json/tips_json/example_images_json/where_to_shoot/best_time/related_category/recommended_tag_ids_json/is_active/sort_order/updated_at`。

  - `example_images_json` 用非空数组（picsum `https://picsum.photos/seed/scene-<id>/600/800` 占位，供 Web/Admin 展示；App 端封面走本地 `localCoverOf` 不受影响）。

  - `is_active=1`，`sortOrder` 排在既有之后，`updated_at` 用当前时间戳。

- 文件位置：`lumira-server/packages/backend/src/database/migrations/`（新文件名，编号顺延，如 `021_system_scenes_add_24.sql`）。

- `builtin_scenes`（usage 注册表）如需计入新场景使用统计，可一并 `INSERT IGNORE`（与 018 同表），非必须。

### Phase E：校验

- `flutter analyze`（在 `lumira_app_flutter`）：确认无报错。

- 后端：typecheck / e2e（`lumira-server` 现有 `backend-ci` 命令），确认迁移可执行。

- 手动验证（真机/桌面）：

  1. 场景库能列出新增 24 个场景，封面显示本地生成的图片。
  2. 点进详情，封面/拍摄参考/滤镜正常，照片计数按真实数据（沿用上一轮已改的逻辑）显示。
  3. 后端 `/api/v1/scenes` 返回到新场景且有 usage 字段。
