## 一、概述

### 1.1 软件简介

「如画 Lumira 摄影辅助应用」（以下简称「如画 Lumira」）是一款面向摄影爱好者与初学者的智能摄影辅助跨平台应用，基于 Google Flutter 3.7+ 框架与 Dart 2.19.6 语言开发，单一代码库即可同时构建 Android、iOS、HarmonyOS（OHOS）、Web、Windows、macOS、Linux 六大平台的原生应用。

软件围绕"取景—构图—姿势—参数—后期"五要素，提供拍摄模板、场景预设、构图叠图、姿势剪影、参数面板、连续打卡、灵感日记、相册管理、主题样式等核心能力，帮助用户在没有专业摄影知识的前提下，也能稳定输出具备美学标准的照片作品。

应用采用「离线优先、零网络权限」的设计理念：所有数据存储于设备本地 SQLite 数据库，不声明 `INTERNET` 权限，不集成任何第三方统计/广告/推送 SDK，不收集任何用户身份信息，最大程度保护用户隐私。

### 1.2 设计原则

| 原则 | 说明 |
|---|---|
| 编辑式留白 | 内容区大量宏观留白，呼吸感优先于信息密度 |
| 内容即界面 | 取景器与照片是主角，UI 控件退让至边缘或悬浮层 |
| 字体强对比 | Serif 衬线标题搭配 Sans 无衬线正文，建立清晰层级 |
| 悬浮层级 | Tab 栏、快门、参数条以悬浮胶囊形式浮于内容之上 |
| 单点缀色 | 品牌金仅用于选中态、关键 CTA、当前模板标记 |
| 离线优先 | 全部功能离线可用，零网络依赖、零用户数据上传 |
| 跨端一致 | 同一 Flutter 代码库覆盖六大平台，行为与视觉一致 |

## 二、功能模块详细说明

「如画 Lumira」共划分为 10 个功能模块（feature），每个模块在 `lib/features/` 下独立成目录，模块内部按 `data`（状态与数据）、`pages`（页面）、`widgets`（模块专属组件）三层组织。

### 2.1 splash 启动页模块

#### 2.1.1 功能描述

启动页负责应用冷启动时的品牌展示与初始化调度。在 splash 页面期间，应用完成数据库 lazy 初始化、主题加载、路由恢复等异步准备工作，随后自动跳转至首页 `home`。

#### 2.1.2 页面列表

| 页面 | 路由 | 文件 |
|---|---|---|
| 启动页 | `/splash` | `lib/features/splash/pages/splash_page.dart` |

#### 2.1.3 核心组件与数据流

- **组件**：品牌 LOGO 居中展示、版本号副标题、品牌金渐变背景。
- **数据流**：
  1. `splash_page.dart` 在 `initState` 中通过 `ProviderScope` 读取 `databaseProvider`，触发 SQLite lazy 初始化；
  2. 同时读取 `appThemeProvider` 与 `userSettingsProvider`，恢复用户上次选择的主题；
  3. 异步任务完成或 1.2 秒计时到达后，使用 `context.go(RouteNames.home)` 跳转首页，替换路由栈。

#### 2.4.4 模板数据结构（.pptpl 格式）

「如画 Lumira」自定义 `.pptpl` 模板格式为自包含 JSON 文件，单文件即包含模板的全部信息（元数据、构图、姿势、相机参数、场景指南、后期处理），可离线导入导出、跨用户分享。结构如下：

```json
{
  "meta": {
    "id": "模板唯一标识",
    "name": "模板名称",
    "author": "作者",
    "version": "版本号",
    "category": "分类",
    "classification": { "tagIds": [...] },
    "tags": ["标签"],
    "price": 0,
    "cover": "封面图（dataURL）",
    "description": "描述",
    "referenceSource": "参考来源"
  },
  "composition": {
    "overlayType": "构图类型（三分法 / 黄金比例 / 对角线 / 引导线 / 网格）",
    "subjectFrame": { "x": 0, "y": 0, "w": 1, "h": 1 },
    "opacity": 0.5,
    "aspectRatio": "3:4"
  },
  "pose": {
    "silhouette": { "type": "builtin | custom", "data": "key 或 dataURL" },
    "position": { "x": 0.5, "y": 0.5 },
    "scale": 1.0,
    "rotation": 0
  },
  "camera": {
    "exposureCompensation": 0,
    "iso": 100,
    "shutterSpeed": "1/200",
    "whiteBalance": "daylight"
  },
  "sceneGuide": {
    "lightDirection": "侧光 45°",
    "shootingDistance": "1.5-2m",
    "background": "背景建议",
    "props": ["道具"],
    "tips": ["贴士"]
  },
  "postProcess": {
    "cropRatio": "3:4",
    "color": { "brightness": 0, "contrast": 0, "saturation": 0 },
    "lut": "warm_film"
  }
}
```

#### 2.4.5 数据流

模板列表通过 `templatesProvider`（FutureProvider）从 `templates_dao` 读取，DAO 内部根据 `category`、`price`、`tag_ids_json` 字段做 SQLite 查询过滤。编辑器保存时将整个模板对象序列化为 JSON，分别写入 `custom_templates` 表的 `composition_json`、`pose_json`、`camera_json`、`scene_guide_json`、`post_process_json` 五个 JSON 字段。

## 三、数据层设计

### 3.1 数据库总体设计

「如画 Lumira」采用 **sqflite**（SQLite）作为本地持久化数据库，所有数据存储于设备本地，不进行任何云端同步。数据库共设计 **5 张表**：

| 表名 | 用途 | 行数规模 | 主键 |
|---|---|---|---|
| `custom_templates` | 自定义模板 | 多行 | `id`（TEXT） |
| `scenes` | 场景预设 | 18 行（预设）+ 用户自定义 | `id`（TEXT） |
| `gallery_items` | 相册照片 | 多行 | `id`（TEXT） |
| `user_progress` | 用户成长 | 单行 | —（无主键，约定仅 1 行） |
| `user_settings` | 用户设置 | 单行 | —（无主键，约定仅 1 行） |

### 3.2 数据库初始化

数据库通过 `lib/core/db/database_provider.dart` 中的 `databaseProvider`（Provider）以 **lazy 初始化**方式提供：

```dart
final databaseProvider = Provider<Database>((ref) {
  // lazy 初始化：首次被读取时才打开数据库连接
  // 后续读取复用同一实例
});
```

数据库文件存放在应用沙箱目录下，应用卸载时自动清除。表名与列名常量统一定义于 `lib/core/db/tables.dart`，避免魔法字符串。

### 3.5 数据流总体架构

```
UI 页面（features/<feature>/pages）
        ↓ 读取 / 监听
Riverpod Provider（StateNotifier / FutureProvider / StateProvider）
        ↓ 调用
DAO 层（core/db/dao/*）
        ↓ 执行 SQL
sqflite Database（core/db/database_provider）
        ↓ 文件 I/O
SQLite 数据库文件（应用沙箱）
```

Riverpod Provider 作为 UI 与 DAO 之间的中间层，负责：
- 缓存查询结果，避免重复 SQL 调用；
- 暴露可监听状态，UI 自动重建；
- 跨模块共享同一份数据（如 `userProgressProvider` 在 home / profile / challenge 多处复用）。

## 六、核心技术实现

### 6.1 相机预览（基于 camerawesome）

**目标**：跨 Android / iOS / HarmonyOS 三端提供统一的实时取景器。

**实现**：

- 使用 `camerawesome ^1.4.0` 包，封装于 `lib/features/capture/widgets/camera_preview.dart`；
- 通过 `CameraAwesomeBuilder.awesome()` 构建预览，自动处理权限请求、生命周期、镜头切换；
- 输出 `CameraState`，包含传感器、闪光灯、对焦、变焦等状态；
- 拍照通过 `state.when(onPhotoMode: (mode) => mode.takePhoto())` 触发，返回 `XFile`。

**关键代码片段**：

```dart
CameraAwesomeBuilder.awesome(
  saveConfig: SaveConfig.photo(),
  onImageForCapture: (xfile) => _handleCapture(xfile),
  sensor: sensor,
  flashMode: flashMode,
  // ...
)
```

### 6.2 构图叠图

**目标**：在取景器上叠加构图参考线，辅助用户构图。

**支持的叠图类型**：

| 类型 | 说明 |
|---|---|
| 三分法 | 9 宫格，主体置于交叉点 |
| 黄金比例 | 黄金分割螺旋 |
| 对角线 | 主对角线 + 副对角线 |
| 引导线 | 自定义引导线 |
| 网格 | 等距网格 |

**实现**：

- 使用 Flutter `CustomPainter` 在 `CameraPreview` 之上绘制叠图层；
- 叠图配置来自模板的 `composition_json` 字段，反序列化为 Dart 对象；
- 通过 `Opacity` 控制叠图透明度（默认 0.5）；
- 支持 `subjectFrame` 主体框、`aspectRatio` 输出比例裁切框。

### 6.3 姿势剪影

**目标**：在取景器上叠加人物姿势剪影，辅助摆姿。

**实现**：

- 内置 SVG 剪影库（位于 `assets/images/`），通过 `flutter_svg` 渲染；
- 模板 `pose_json.silhouette.type` 区分 `builtin`（内置 key）与 `custom`（用户上传 dataURL）；
- 支持 `position`（位置）、`scale`（缩放）、`rotation`（旋转）三参数变换；
- 用户可在模板编辑器中上传自定义剪影图，序列化为 base64 存入 `pose_json`。

### 6.4 模板烘焙

**目标**：将拍摄时的取景器画面、构图叠图、姿势剪影、参数面板"烘焙"为一张完整作品图，导出为 JPEG。

**实现**：

- 使用 `RepaintBoundary` + `toImage` 将取景器画面 + 叠图层整体截图；
- 通过 `image ^4.0.16` 包对像素数据进行后期处理（亮度 / 对比度 / 饱和度 / 色温 / 色调 / LUT）；
- `gpu_image ^1.0.0` 提供 GPU 加速的滤镜处理，应用于 15 种 LUT 滤镜；
- 暗角、颗粒、锐化通过卷积核或随机噪声实现；
- 最终通过 `image.encodeJpg` 导出，写入 `gallery_items` 表。

**烘焙流程**：

```
取景器帧 + 叠图层
    ↓
RepaintBoundary.toImage() → Uint8List
    ↓
image 包像素处理（亮度/对比度/饱和度/色温/色调）
    ↓
gpu_image 应用 LUT 滤镜（15 种预设）
    ↓
暗角 + 颗粒 + 锐化后处理
    ↓
image.encodeJpg → JPEG 二进制
    ↓
gallery_dao.insert 写入 gallery_items
```

### 6.5 横竖屏自适应

**目标**：拍摄页与图像编辑页在横竖屏切换时，叠图、控件、布局自动适配，不丢失状态。

**实现**：

- 通过 `MediaQuery.of(context).orientation` 监听设备方向；
- `CapturePage` 使用 `OrientationBuilder` 重建布局：
  - 竖屏（`portrait`）：底部悬浮快门、顶部参数条；
  - 横屏（`landscape`）：右侧悬浮快门、左侧参数条；
- 叠图层通过 `AspectRatio` 强制保持模板设定的输出比例（如 3:4 / 16:9），与设备方向解耦；
- 状态通过 `captureStateProvider`（StateNotifier）持久化，旋转时不丢失。

### 6.6 .pptpl 模板导入导出

**目标**：支持用户将模板以 `.pptpl` 文件格式离线分享。

**实现**：

- 导出：将 `custom_templates` 表的一行序列化为完整 JSON（含 `meta` / `composition` / `pose` / `camera` / `sceneGuide` / `postProcess` 六段），写入文件；
- 导入：读取 `.pptpl` 文件，反序列化为 Dart 对象，校验 `version` 字段后通过 `TemplatesDao.insert` 写入数据库；
- 文件扩展名 `.pptpl` 是「如画 Lumira」自定义格式，本质为 UTF-8 编码的 JSON 文本。

### 6.7 18 个场景预设与 15 种 LUT 滤镜

**18 个场景预设**：在首次启动时通过 `scenes_dao.insert` 批量写入 `scenes` 表，覆盖窗光、日落逆光、霓虹、烛光、海边、森林、城市、居家、咖啡馆、影棚、治愈、孤独等场景，每个场景包含 `filter_json`（氛围滤镜配置）、`vibe`（情绪主标题）、`tips_json`（拍摄贴士）、`where_to_shoot`（出片地点）、`best_time`（最佳时间）等完整字段。

**15 种 LUT 滤镜**：作为枚举常量定义于 `lib/features/capture/data/` 中，每款 LUT 对应一个 3D 颜色查找表（CUDA / CUBE 格式），在模板烘焙阶段通过 `gpu_image` 应用于像素数据。LUT 标识存储于 `gallery_items.lut` 字段，便于后期回溯。

## 七、性能与优化

### 7.1 性能目标

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 相机启动 | < 1s | 从点击 Tab 到取景器画面出现 |
| 叠图渲染 | < 16ms/帧 | Flutter DevTools 帧率监测（60 FPS） |
| 快门响应 | < 100ms | 从按下快门到捕捉完成 |
| 模板烘焙（1080P） | < 2s | 从触发烘焙到 JPEG 写入完成 |
| 模板列表加载 | < 500ms | 从进入页面到列表渲染完成 |
| 应用冷启动 | < 3s | 从图标点击到首页可交互 |
| 数据库首查 | < 50ms | sqflite 单表查询 |
| 主题切换 | < 100ms | 从点击到全 App 重建完成 |

### 7.2 优化措施

| 优化点 | 措施 |
|---|---|
| 数据库 lazy 初始化 | `databaseProvider` 仅在首次读取时打开连接，避免冷启动开销 |
| Riverpod Provider 缓存 | FutureProvider 自动缓存查询结果，避免重复 SQL |
| 主题 Token 编译期常量 | 8 套 Token 均为 `static const`，零运行时开销 |
| 图像处理 GPU 加速 | LUT 滤镜通过 `gpu_image` 走 GPU 着色器，CPU 仅处理像素级调整 |
| `RepaintBoundary` 隔离重绘 | 取景器与叠图层隔离，避免全局重绘 |
| `const` Widget 优化 | 凡可声明为 `const` 的 Widget 均显式标注，减少 rebuild |
| 路由懒加载 | GoRouter 默认懒加载页面，未访问页面不实例化 |
| 图片资源缓存 | `assets/images/` 下的预设图片由 Flutter 引擎缓存 |
| 单行表免主键查询 | `user_progress` / `user_settings` 单行表通过约定查询，无需主键索引 |

## 八、安全与隐私

### 8.1 隐私设计

「如画 Lumira」以"零网络权限、零数据上传"为最高隐私原则：

| 维度 | 实现 |
|---|---|
| 网络权限 | **不声明 `INTERNET` 权限**，应用无法发起任何网络请求 |
| 用户身份 | 不收集任何账号、手机号、设备标识（IMEI / IDFA / OAID） |
| 第三方 SDK | **不集成任何统计 / 广告 / 推送 / 崩溃收集 SDK** |
| 数据存储 | 全部数据存储于应用沙箱内的 SQLite，卸载即清除 |
| 相机权限 | 仅在拍摄相关页面按需请求，可随时在系统设置撤销 |
| 相册权限 | 仅在用户主动导出时请求，不主动扫描系统相册 |
| 文件导出 | 导出文件不含任何跟踪标识或水印以外的元数据 |

### 8.2 数据安全

| 维度 | 实现 |
|---|---|
| 本地数据加密 | 依赖设备级文件系统加密（Android Keystore / iOS Data Protection） |
| 敏感字段 | 不存储密码、Token、支付信息等任何敏感数据 |
| 模板来源 | 用户自建或本地导入 `.pptpl` 文件，不来自网络 |
| 崩溃日志 | 不上传任何崩溃日志到服务器 |
| 权限最小化 | 仅申请相机、麦克风（拍摄）、存储（导出）三项必要权限 |

### 8.3 合规说明

- 应用不面向 14 岁以下儿童提供，但所有功能均适合未成年人使用；
- 不含任何付费引导跳转外部链接（模板付费为本地虚拟解锁，不涉及真实货币交易）；
- 不含任何用户生成内容（UGC）的分享与发布功能，照片仅存本地；
- 18 个场景预设与 8 个免费模板 + 4 个付费模板均为应用内预制内容，无网络更新机制。
